
Пользователь спрашивает совета: куда лучше перенести хостинг проекта — на Vercel или Railway. Это вопрос-консультация, не задача на изменение кода. Отвечаю прямо без плана реализации.

## Краткий анализ проекта

- **Стек:** Vite + React + TypeScript (чистый SPA, см. `vite.config.ts`, `package.json`).
- **Backend:** Supabase (Edge Functions + БД) — внешний, от хостинга фронта не зависит.
- **Сборка:** `npm run build` → статические файлы в `dist/`.
- **Роутинг:** React Router (`BrowserRouter`) — нужен SPA fallback на `index.html`.
- **Env переменные:** Supabase URL и anon key захардкожены в `src/integrations/supabase/client.ts` (env переменные не нужны на хостинге).
- **Нет SSR, нет Node-сервера, нет API роутов на фронте.**

## Рекомендация: Vercel

Для этого проекта **Vercel — лучший выбор**, и вот почему:

### Vercel (рекомендую)
**Плюсы для вашего проекта:**
- Идеально заточен под статические SPA (Vite/React) — zero-config деплой.
- Автоматический SPA fallback (через `vercel.json` с `rewrites`) — одна строка конфига.
- Глобальный CDN из коробки → быстрая загрузка для UA/RU аудитории.
- Бесплатный тариф щедрый: безлимит статики, 100GB трафика/мес.
- Простая привязка домена `lystosyk.com` (DNS через Vercel).
- Preview-деплои на каждый git push.
- Аналитика и Web Vitals встроены.

**Минусы:**
- Если в будущем захотите перенести Edge Functions с Supabase — Vercel Functions имеют свои лимиты (но вам это не нужно, всё уже на Supabase).

### Railway
**Плюсы:**
- Хорош, если нужен **долгоживущий Node/Docker сервер** (БД, воркеры, бэкенд на Express).
- Гибкость для нестандартных конфигураций.

**Минусы для вашего проекта:**
- Это **overkill для статического SPA** — вы будете платить за контейнер, который просто отдаёт `dist/`.
- Нет встроенного CDN — медленнее на удалённых регионах.
- Нет бесплатного тарифа (с 2023): минимум $5/мес trial, потом pay-as-you-go.
- Нужно вручную настраивать nginx/serve для SPA fallback.

## Что нужно сделать для деплоя на Vercel

1. Подключить GitHub-репо проекта на vercel.com.
2. Vercel автоматически определит Vite (Framework Preset: Vite, Build: `npm run build`, Output: `dist`).
3. Добавить файл `vercel.json` в корень для SPA-роутинга:
   ```json
   {
     "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
   }
   ```
4. Перенести домен `lystosyk.com` через DNS (A/CNAME записи).
5. Supabase продолжит работать как есть — никаких изменений в коде.

## Итог

**Vercel** для вашего кейса. Railway имеет смысл только если планируете отдельный Node-бэкенд — для чистого Vite + Supabase это лишние деньги и сложность.

Если хотите — могу подготовить план миграции с созданием `vercel.json` и инструкциями по DNS.
